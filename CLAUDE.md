# pins-clarte — contexte pour Claude Code

Ce fichier est chargé automatiquement au démarrage de chaque session Claude Code sur ce dépôt. Le README.md contient le détail complet et le pourquoi de chaque règle — ce fichier n'en est qu'un résumé opérationnel pour ne pas répéter les erreurs déjà corrigées.

## Le compte

"Clarté Mentale | Stress & Énergie" — compte Pinterest francophone centré sur **le stress, la procrastination et le sommeil**, et leurs thèmes associés : `sommeil`, `systemenerveux`, `fatiguementale`, `alimentation`, `procrastination`, `somatisation`, `blocagemental`, `posturesantistress`, `energie` (chacun a son propre board Pinterest — voir `TABLEAUX` dans `.github/workflows/pins.yml`).

Le pipeline (`pins.yml` + `videos.yml`, déclenchés par cron-job.org) publie automatiquement, **sans aucun contrôle de pertinence** : il envoie le prochain pin non publié, choisi par rotation entre thèmes (pas dans l'ordre du tableau — voir `choisir_pin_equilibre()`). Toute la responsabilité de cohérence repose sur ce qui est ajouté à ces fichiers — voir la section "Cohérence du contenu" du README avant d'ajouter quoi que ce soit.

## ⚠️ Règle critique : le pipeline publie depuis `main`, pas depuis une branche de session

**Incident du 27/09/2026** : une session entière de corrections faite sur une branche jamais fusionnée dans `main` a laissé le compte publier l'ancienne banque non corrigée pendant toute une journée (8 pins hors-sujet publiés avant détection). Le pipeline automatique (cron-job.org toutes les 2h) committe en continu sur `main`, 24h/24, indépendamment de toute session Claude Code.

**En début de session** : `git fetch origin main` pour voir où en est la production réelle.
**Avant de considérer un travail terminé** : la correction doit être visible sur `origin/main`, pas seulement commitée sur une branche locale ou de travail. Fusionner immédiatement, ne jamais reporter "à la prochaine session".
**Avant de pousser vers `main`** : fusionner d'abord les commits automatiques récents (`git merge origin/main`) pour éviter un rejet.

Détail complet : `docs/pinterest-projet/05-process-operationnel.md`.

## Règles impératives (déjà appliquées, à ne pas régresser)

1. **Zéro duplicata.** Titres et quasi-titres uniques (vérifier avec `difflib.SequenceMatcher`, pas juste l'égalité stricte), images jamais réutilisées à l'identique. Pinterest pénalise le contenu dupliqué. **Depuis le 07/10/2026, le pipeline refuse lui-même les doublons** (`outils/anti_doublons.py`, appelé par `pins.yml` et `videos.yml` avant de choisir) : titre identique une fois normalisé, titre proche (≥ 0,72) ou même sujet (mots-clés communs, avec synonymes), comparé à `historique*.json`, aux kits Idea Pins, à `titres_en_ligne.json` et aux pins réellement en ligne lus via Composio ; image prête ou image finale déjà publiée aussi refusée. **Depuis le 08/10/2026 (consigne de l'utilisateur : « aucun doublon au niveau des images »), aucune photo de fond n'est jamais réutilisée** : `outils/photos_uniques.py`, appelé par `pins.yml` et `videos.yml`, écarte toute photo déjà publiée (pins, carrousels, vidéos) ; sans photo inédite, le pipeline publie moins plutôt que de réutiliser (journal section 41). Toute photo ajoutée à `fonds/` doit être nouvelle (vérifier qu'elle n'est pas la copie d'une photo existante) ; `carousel.yml` n'applique pas encore la règle. **Recharge de photos** : `photos.yml` (accord de l'utilisateur, 08/10/2026) télécharge les photos libres de droits listées dans `photos_a_importer.json` vers `photos_attente/` (jamais utilisée par le pipeline) ; tri à l'œil obligatoire avant tout passage dans `fonds/` (pas de texte dans l'image, rien de suggestif ni hors sujet, pas de quasi-jumelles, empreinte contre les photos existantes, recadrage vérifié) ; registre `photos_sources.json`. **Consigne de l'utilisateur (08/10/2026) : ne rien payer pour les images** — uniquement des photos libres de droits gratuites (Pexels, Pixabay, Unsplash via son connecteur, à privilégier) et le quota gratuit de Hugging Face ; jamais Claude Imagine payant, crédits Figma, OpenAI (ne pas renseigner `OPENAI_API_KEY`) ni aucun abonnement. **Avant de pousser toute recharge de `pins.json`/`videos.json` : `python3 outils/verifier_banque.py` doit afficher 0 doublon**, puis relire les sujets à la main (le contrôle automatique ne voit que les titres : le 07/10, il n'aurait repéré qu'environ un quart des 242 doublons de sujet retirés à la main).
2. **Cohérence texte + image avec le périmètre du compte** avant tout ajout à `pins.json` — pas de contenu générique (recette, déco...) sans lien explicite avec stress/sommeil/mental. Le thème est déterminé par le **premier hashtag** de la description (`deviner_theme()`), pas par la présence du mot-clé ailleurs dans le texte.
3. **Board `alimentation` ("Alimentation et stress") : uniquement l'angle "l'alimentation diminue le stress".** Jamais sommeil ou énergie seuls sur ce board (ces angles existent déjà via les thèmes `sommeil`/`energie`).
4. **Lien de destination conditionnel.** `LIEN_PAGE` (page de capture d'une formation systeme.io) n'est ajouté au pin que pour les thèmes réellement couverts par le contenu de la formation — **sommeil et les mécanismes du stress au sens large** (nervosité, tensions physiques, blocages, postures), pas l'énergie/fatigue en général. Voir `THEMES_SANS_LIEN` dans `pins.yml`/`videos.yml` : actuellement `alimentation`, `procrastination`, `energie` et `fatiguementale` sont hors périmètre → `lien` vide pour ces thèmes, et leur CTA ne doit jamais promettre un contenu "dans le guide gratuit" ou inviter à cliquer (rien derrière). **Contenu réel du guide (page de capture vérifiée le 29/09/2026)** : « Quand le cerveau refuse de dormir » — routine anti-rumination à faire au lit, exercices pour calmer le mental, calendrier de 30 jours, sans matériel. Tout appel au guide doit décrire ce contenu (sommeil, ruminations, mental du soir) ; sur un pin stress/corps, faire le pont (« si ce stress te suit jusqu'au lit… ») au lieu de promettre un contenu stress/corps absent du guide. **Depuis le 07/10/2026** (autorisé) : carte « guide » avec maquette dessinée du guide sur l'image des pins avec lien, pastille « À GARDER · enregistre l'épingle » sur les pins sans lien, et `utm_content` unique par pin (journal section 36). **2e guide « Le plan anti-cortisol en 7 jours » (07/10/2026)** : **actif depuis le 07/10/2026** dans `pins.yml` (`LIEN_GUIDE_CORTISOL` = https://lp.contactapaisement-mental.fr/63d489c7, page créée par l'API, PDF téléchargé sur la page de remerciement, pas d'e-mail : plan gratuit systeme.io limité à 3 tunnels / 1 règle d'automatisation, déjà tous utilisés ; `guides/page-systeme-io-cortisol.md`, journal section 38) — **ne plus changer l'adresse de cette page** (les épingles publiées ne sont pas modifiables) ; une fois actif, `energie`/`alimentation` et les pins `"guide": "cortisol"` y mènent avec leur `description_guide_cortisol`, les pins `"guide": "aucun"` restent sans lien (journal section 37). **08/10/2026 (autorisé)** : `videos.yml` suit la même logique (plan anti-cortisol pour energie/alimentation et `"guide": "cortisol"`, champ `fin_avec_lien` = dernière scène renvoyant au guide, utilisée seulement si la vidéo a un lien) ; rotation des pins : thème sommeil ×3 (`POIDS_THEME`), car 14 des 15 clics sortants du 24/09 au 07/10 viennent de sujets nuit/soir/ruminations — garder un stock de pins sommeil inédits (journal section 40). **Clics sortants (29/09/2026)** : 75 % des pins avec lien portent un appel au guide (toutes les fins différentes), les images des pins avec lien portent le bandeau « GUIDE GRATUIT · lien dans l'épingle », la rotation fait passer les thèmes avec lien deux fois plus souvent, et la phrase d'enregistrement n'est plus ajoutée quand elle écraserait l'appel au guide. **Incident du 28/09/2026** : un pin thème `energie` (premier hashtag `#energie`, contenu 100% alimentation/petit-déjeuner) avait échappé à la règle du board alimentation en changeant de hashtag en tête, et a été publié avec un lien alors que le guide ne traite pas ce sujet — piège à surveiller : vérifier que le **contenu réel** du pin correspond à ce que couvre la formation, pas seulement son thème/premier hashtag.
5. **Titres travaillés, descriptions longues et SEO.** Corps de description (hors hashtags) visé entre 380 et 450 caractères, total ≤ 495-500 (limite Pinterest, sinon troncature automatique par le script). Mots-clés naturels, pas de bourrage. **Mise à jour du 28/09/2026 (données Pinterest Analytics réelles, connecteur Composio) : privilégier les titres à chiffre/listicle** ("5 clés pour...", "7 signes de...") — format des pins historiques les plus performants du compte — **et 8-10 hashtags** (au lieu de 5, dans la limite du plafond 495-500 total ci-dessus), le premier restant seul déterminant du board. Détail : `docs/pinterest-projet/03-regles-editoriales.md` section 6-7. **Mise à jour SEO du 07/10/2026** (`analyse-seo-2026-10-07.md`) : titres de **35 à 55 caractères, mot-clé recherché en tête** (Pinterest n'en affiche que ~40 ; meilleurs pins du compte ≈ 44) ; mots-clés prioritaires : cortisol, système nerveux / nerf vague, gestion des émotions, charge mentale / burn-out, routine du soir ; jamais somatisation, insomnie ou cohérence cardiaque comme mot-clé principal (absents des recherches Pinterest France).
6. **CTA variés, pas systématiques.** Ne jamais répéter la même formule de fin d'un pin à l'autre. Environ un quart des pins peuvent se terminer sans CTA explicite (fin informative).
7. **Ne jamais toucher aux pins déjà publiés** (présents dans `historique.json` par titre exact) — modifier leur texte est sans effet (jamais relu) et changer leur titre risquerait de les faire republier comme "nouveaux".
8. **Format infographie (`points_image`, 28/09/2026).** Champ optionnel dans `pins.json` : liste de 2-4 points courts. Quand présent, `pins.yml` dessine une infographie (titre + liste numérotée) via `dessiner_infographie()` au lieu d'une simple phrase — format identifié comme le plus performant historiquement sur ce compte. Toujours du texte dessiné par PIL, jamais par une IA d'image. Détail : section "Format infographie" du README. **Depuis le 29/09/2026 : test A/B de visuel** — `pins.yml` alterne strictement un visuel **clair** (fond crème, étiquette de thème, titre en haut, étapes en cartes numérotées, photo recadrée sur sa zone la plus nette, couleur par thème — inspiré des meilleurs Idea Pins du compte) et l'ancien visuel **sombre** ; le champ `design` de `historique.json` indique lequel, pour comparer les statistiques après 2-3 semaines avant de trancher. Chaque pin reçoit aussi un **texte alternatif** (`texte_alternatif()`). **Règle utilisateur du 29/09/2026 : le texte ne doit jamais couper/recouvrir la photo** — dans les deux visuels, la photo et le texte sont dans des zones séparées (visuel sombre : photo en haut recadrée sur sa zone nette, texte dans un bandeau sombre en dessous ; visuel clair : cartes puis photo), avec réduction automatique de la taille du texte ; les fonctions de dessin renvoient leurs zones, vérifiées par script sur toute la banque (0 chevauchement sur 340 rendus le 29/09) — à revérifier après tout ajout à `pins.json`. Visuel clair : la photo est prioritaire sur la taille du texte (réduction du texte des cartes, des marges internes et des espacements avant de renoncer à la photo) — 29/09 : 0 visuel sans photo et 0 chevauchement sur les 564 rendus (282 pins × 2 visuels). **30/09/2026 (plainte utilisateur : images coupées)** : photos recadrées sur la tête du sujet (`fonds_cadrage.json`, produit par `outils/cadrage_fonds.py` et vérifié à l'œil — **à relancer après tout ajout de photo dans `fonds/`**) au lieu de la seule « zone la plus nette » (qui tombait sur un pull, des mains ou un bureau) ; visuel clair : photo ≥ 300 px (220 avant, bande trop fine) et le titre rétrécit avant le texte des étapes — 502 rendus : 0 sans photo, 0 chevauchement, étapes à 36-38 pt.
9. **Rythme de publication (consigne du 29/09/2026, mise à jour le jour même) : uniquement 10 pins normaux/jour (`pins.yml`) + 1 vidéo/jour à 18h30 Paris (`videos.yml`). PAS de carousel quotidien** — l'utilisateur a arrêté le carousel/Idea Pin quotidien demandé plus tôt le même jour : ne pas créer de tâche cron-job.org pour `carousel.yml`, ne pas en publier sans nouvelle demande explicite. Historique de la piste Idea Pin, si elle est un jour relancée : Les pins historiques les plus performants du compte sont tous du format natif Pinterest `creative_type: IDEA` (voir `04-journal-decisions.md` section 12) — s'appuyer sur ce qui marche vraiment (titres à chiffre, CTA type "sauve cette épingle"...), **sans jamais dupliquer un pin déjà publié**. **Contrainte technique** : aucun outil disponible (Pinterest API v5 via Composio) ne permet de créer une vraie Idea Pin — `PINTEREST_CREATE_PIN` ne supporte que image / carousel (2-5 images) / vidéo. Le **carousel** est donc utilisé comme substitut le plus proche, pas une vraie Idea Pin. **Publication automatisée depuis le 29/09/2026** par `.github/workflows/carousel.yml` (premier succès : pin `600175087889887532`) : pioche un pin non publié ayant `points_image` dans `pins.json`, génère 1 slide de couverture + 1 slide par point (fond différent par slide), publie via l'API Composio (`PINTEREST_CREATE_PIN`, secret GitHub `COMPOSIO_API_KEY`, connexion Pinterest créée dans l'**Aire de jeux** du projet Composio `yacinenettour_workspace_first_project` — la connexion MCP de session est un espace distinct, invisible pour cette clé), puis inscrit le titre dans `historique.json` (le pipeline classique ne le republiera pas). Même règle `THEMES_SANS_LIEN`. Workflow conservé pour un lancement manuel éventuel, sans déclenchement automatique. **Fichiers `.github/workflows/*`** : poussés sur `main` depuis la session uniquement avec l'autorisation explicite de l'utilisateur pour ce changement (accepté le 29/09 pour `videos.yml`, après validation par simulation) ; sinon fournir le fichier complet validé à coller dans l'éditeur GitHub — jamais d'édition partielle ligne par ligne (source de 3 erreurs de syntaxe le 29/09). **Règle du 29/09/2026 sur les slides** : jamais le même fond photo réutilisé sur les différentes images d'un même carousel (un fond différent par slide, pas juste un texte différent sur le même fond) ; contenu de chaque slide plus riche qu'une seule courte phrase reprise telle quelle du champ `points_image` (ajouter du contexte/détail par slide, pas une répétition minimaliste).

## Fichiers clés

- `pins.json` : banque de pins (texte). `historique.json` : suivi anti-répétition (titres déjà publiés).
- `videos.json` / `historique_videos.json` : équivalent pour les Video Pins.
- `fonds/` + `fonds_themes.json` : photos de fond par thème. **Photo dédiée (07/10/2026)** : champ optionnel `"photo"` d'un pin (nom de fichier dans `fonds/`) → `pins.yml` l'utilise à la place de la rotation par thème (si elle fait ≥ 800 px de large pour le visuel clair) ; ces photos sont classées `"dedie"` dans `fonds_themes.json` pour rester hors rotation. Liste à générer : `outils/photos_dediees_a_faire.json`.
- `prompts/system-prompt-pin-seo.md` : prompt système pour un futur module IA Make.com (image → métadonnées), flux distinct et pas encore connecté au pipeline actuel (texte → image).
- `pins_saisonniers.json` : pins de janvier mis de côté (trop tôt pour les publier) — **à insérer en tête de `pins.json` début décembre 2026** puis `verifier_banque.py` (qui les compte déjà dans son contrôle).
- `kits_idea_pins/` : kits Idea Pins à publier à la main par l'utilisateur (slides + `texte.txt`) — leurs titres sont hors `historique.json` : les inclure dans le contrôle anti-doublon de toute recharge de `pins.json`.
- `site/` : **site web www.contactapaisement-mental.fr** (adresse principale avec www, la racine y redirige) (pont Pinterest → articles → guides gratuits → formation). Sources dans `site/contenu/` (accueil = `accueil.html`, page unique sombre au tutoiement, polices installées sur le site), génération `python3 site/outils/construire.py`, mise en ligne `site/outils/publier.sh` (branche `gh-pages`, GitHub Pages). Règles : sujet santé → chaque affirmation sourcée, section « Quand consulter », aucune promesse ; ne promettre des guides et de la formation que leur contenu réel ; photos du site réservées dans `photos_utilisees_hors_historique.json`. Format des articles (09/10/2026, consigne utilisateur) : chaque partie commence par une réponse directe ou une définition, tableaux comparatifs, études nommées avec université + revue + année (affiliation vérifiée, jamais devinée) ; page `/methode-editoriale/` à tenir à jour ; ne jamais inventer de diplôme ou de vécu pour l'auteur. Pages thème (`themes` dans `site.json`), rappel du guide au milieu des articles ; test de stress et d'anxiété `/test-stress-anxiete/` (GAD-7 mot pour mot + 6 questions d'orientation, profils ; GAD-7 ≥ 10 → consultation d'abord et jamais la formation, ≥ 15 → aucun produit ; PSS seulement avec autorisation Mapi + traducteur obtenue par l'utilisateur) ; audios de respiration guidée `/respiration-guidee/` (MP3 sans voix générés par `site/outils/audios_respiration.py`, à relancer si on change le rythme ou les sons) ; mesure d'audience Cloudflare Web Analytics (sans cookie) active depuis le 09/10/2026 (`mesure` dans `site.json`, mentions légales à jour ; ne jamais ajouter d'outil à cookies ni de publicité sans accord de l'utilisateur et mise à jour des mentions légales). Journal section 42.
- `docs/pinterest-projet/` : documentation complète et autoportante (vue d'ensemble, architecture, tableaux, règles éditoriales, journal des décisions, process opérationnel) — voir son README pour l'index.

## Avant de considérer une tâche terminée

**Modifier un pin déjà en ligne (lien, titre, description) est impossible par l'API** (`PINTEREST_UPDATE_PIN` → 401 `pin_edit`, constaté les 29 et 30/09/2026) : préparer la liste et laisser l'utilisateur le faire à la main — ne pas retenter. Voir `docs/pinterest-projet/liens-anciens-pins.md`.

**Publication : vérifier sur Pinterest lui-même**, jamais se fier à un run GitHub « success » ni à un HTTP 200 de Make/Composio (incident du 29/09/2026 : 5 vidéos inscrites « publiées » depuis le 25/09, aucune en ligne). Connecteurs : Pinterest via Composio (`PINTEREST_LIST_PINS`, `PINTEREST_GET_PIN`) ; Make via son API sur **`eu2.make.com`** (le connecteur Composio `make` vise `us2` et échoue en 401). Détail : `04-journal-decisions.md` section 16.

Toujours revérifier avec un script Python (pas à l'œil) : 0 doublon exact, 0 quasi-doublon, longueurs de titre/description dans les limites, routage de thème/board préservé (premier hashtag inchangé sauf intention explicite), pins déjà publiés intacts. Committer et pousser sur la branche en cours seulement après ces vérifications.
